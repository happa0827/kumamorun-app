# ドメインと音は Rust、Firebase は WebView に置く

Kumamorun はトレイに隠れていても時間どおりに鳴ることが中心の機能だが、Tauri の `backgroundThrottling` は Windows で未対応で、隠れた WebView のタイマーは止まる恐れがある。そこでタイマー、スタート制限の監視、失敗と進化の判定、端末ローカルの保存、音の再生は Rust が持ち、WebView は表示と入力だけを担当する。

Firebase JS SDK だけは WebView に残す。REST API には `onDisconnect` がなく、Rust へ移すと、アプリの異常終了時に `liveStatus` をオフラインへ切り替えられなくなるためである。`status-kumamorun` は `appRunning` と `phase` だけで停止を判定しており、`updatedAt` の鮮度を見ていない。

## Consequences

- この配置は Tauri 移行の間の決定である。Firebase 以外の DB への置き換えを検討中で、移行完了後に別作業として扱う。差し替えられるよう、Rust のドメインと同期処理の間に境界を置く。
- トレイ常駐中も WebView の同期が続くことは、Windows 実機（release ビルド）で確かめた（2026-11-07）。
  - 隠れた状態で 139.8 分測った。Rust の tick は 8382/8382 が WebView に届き、`setInterval` の最大間隔は 1.0 秒で、凍結や間引きは起きなかった。
  - Firebase への書き込みは 419 回で、更新間隔の最大は 20.7 秒だった。
  - 切断は 58 分後に 1 回あり、2.7 秒で自動復帰した。隠れたことが原因かは区別できていない。一過性と判断し、下の再接続処理で吸収する。WebLock は試していない。
- 他の検証も Windows 実機で成功した。
  - 切断検知: アプリを強制終了してから `appRunning` が `false` になるまで 1 秒以内だった。
  - 最前面: ブラウザーの全画面、動画プレーヤーの全画面、ゲームで確認した。
  - 音: 出力先の指定と、隠れた状態での再生を確認した。
- Firebase の接続が切れると、サーバー側で `onDisconnect` が一度動き、登録は消える。そのため `.info/connected` が `true` になるたびに、次を順に行う。
  1. `onDisconnect`（`appRunning=false`）を登録し直す。
  2. Rust から最新の状態を取り直し、`liveStatus` を書き直す。
- 状態の持ち主は Rust である。WebView は状態を持たず、Firebase へ書くだけにする。
- 短い切断の間、`status-kumamorun` が一瞬オフラインを表示することは許容する。`users/{uid}` と `liveStatus` のスキーマは変えない。
- 切断と再接続の回数を端末ローカルのログに残し、頻度が高ければ見直す。
- 当日の統計と直近7日の履歴は、この端末（Rust）の値を正とする。クラウドの値は、この端末に無いものを補うためだけに取り込む（Electron 版は逆にクラウドを正としていた）。
  - 今日の記録がこの端末に無いときだけ、クラウドの今日を採る。履歴は、この端末に無い日だけ補う。
  - `dailyStats` が評価前の過去の日（直近7日以内）なら、その日が成功のとき進化を1つ保留にする。Electron 版が最後に記録した日を、この端末が初めて評価する移行時のため。同じ日は履歴に入るので、二重には進化しない。
  - 取り込みが済むまで、この端末の記録は書かない。空の記録でクラウドの前日分を上書きしないため。
  - 複数の PC で同じアカウントを使い、同じ日に別々に遊ぶ使い方は、回数が合わなくなりうる。対象外とする。
- 進化は Rust が成長か開花かを決め、クラウドには「読んだ段階のままのときだけ書く」トランザクションで反映する。3回続けて負けたときは保留に戻し、二重にも欠落にもしない。花の加算は、段階の書き込みに成功した後に行う。その間にアプリが終了すると、花を失いうる（Electron 版と同じ）。
