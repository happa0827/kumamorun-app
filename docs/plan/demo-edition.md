# デモ版と完全版

オリジナルのキャラクターを守るため、アプリをデモ版と完全版に分ける。サイトで承認したアカウントだけが完全版になる。
判断の理由は [ADR 0003](../adr/0003-demo-edition.md)、用語は [GLOSSARY.md](../../GLOSSARY.md)（デモ版、完全版、承認）に従う。

アプリとサイトの約束は、この文書の「スキーマ」「API」「画像」。変えるときは、両方のリポジトリで同時に直す
（[void-migration.md](void-migration.md) と同じ扱い）。

## 分担

| 担当 | 範囲 |
|---|---|
| このリポジトリ（kumamorun-tauri） | アプリ側。**実装済み**（下の「アプリの動き」） |
| 別エージェント（kumamorun-projects） | サイト側。スキーマ、API、承認の画面、画像の置き場所、既存アカウントの移行 |
| 共同 | 公開の順番（下の「公開の手順」） |

## デモ版と完全版の違い

| | デモ版 | 完全版 |
|---|---|---|
| キャラクター | 成長段階のシルエット（アプリに同梱） | 本来の画像（サーバーから受け取る） |
| 進化と開花 | 反映しない。成功日の進化は保留のまま残り、完全版になったら反映する | 使える |
| スタート制限 | 効かず、変えられない。設定済みの内容は残り、完全版になると戻る | 使える |
| タイマー、休憩の猶予、失敗、記録、読み上げ、音、集中、ミニ、ライブ状況 | 使える | 使える |

ログインしていない端末は、デモ版。

## スキーマ（D1）

`approvals` を足す。アカウントにつき0か1行。行があれば完全版。

```sql
CREATE TABLE approvals (
  account_id  TEXT PRIMARY KEY,
  approved_at INTEGER NOT NULL,
  approved_by TEXT,                    -- 承認した管理者の account_id。移行で入れた行は NULL
  note        TEXT                     -- 例: "既存の利用者（2026-11-23 時点）"
);
```

### 既存アカウントの移行

**今使っている人は完全版のまま**にする。このマイグレーションを、公開の時点で存在するアカウントすべてに対して1回だけ流す。

```sql
INSERT INTO approvals (account_id, approved_at, approved_by, note)
SELECT id, unixepoch() * 1000, NULL, '既存の利用者'
FROM user                               -- Void（Better Auth）のユーザーのテーブル
WHERE id NOT IN (SELECT account_id FROM approvals);
```

2026-11-15 の切り替えで、利用者は全員サイトに登録し直している。そのため、アカウントを対象にすれば漏れはない。

## API

すべて `/api/app/v1/…`。認証は今までと同じ（`Authorization: Bearer <端末のトークン>`）。

### `GET /sync` と `POST /import` の応答に足すキー

| キー | 型 | 内容 |
|---|---|---|
| `edition` | `"full"` か `"demo"` | `approvals` に行があれば `"full"`。アプリは、`"full"` 以外（欠けている場合を含む）をすべてデモ版として扱う。 |
| `charactersVersion` | 文字列か `null` | 完全版の画像の版。画像を差し替えたら変える。アプリは、この値が変わったときだけ画像を取り直す。`[A-Za-z0-9._-]` で1〜64文字。中身の形（時刻と乱数）には頼らず、そのまま比べて、そのまま `?v=` に渡す。デモ版には `null` を返す。完全版でも、まだ一度も公開していなければ `null`。 |

例: `{ "restrictions": …, "daily": …, "history": …, "stage": 3, "flowers": 2, "edition": "full", "charactersVersion": "2026-11-23T06.30.12.345Z-1a2b3c4d5e6f" }`

### `GET /characters/{key}?v={charactersVersion}`（新規）

完全版の画像を1枚返す。返すのは公開した組だけ（管理者が置いただけの下書きは返さない）。

- **`?v=` に `/sync` の `charactersVersion` を付ける。** アプリは10枚すべてを同じ `v` で取る。取っている途中に新しい版が公開されても、同じ版の組を取り終えられる。
- その版がない、または消したあと（下の「画像の置き場所」）なら `404`。今の版には切り替えない。アプリは1枚でも取れなければ置かずにシルエットのままにし、間隔を延ばして取り直す。
- `?v=` を付けなければ、配っている版の組から返す。`?v=` に対応する前のアプリのため。この形では、取っている途中に公開されると、新旧の混ざった組になることがある。
- 完全版のアカウント: `200`、`Content-Type: image/png`、本文は PNG。2MB 以下。`Cache-Control: private, no-store`。
- デモ版のアカウント: `403`（`{ "error": "demo_edition" }`。`?v=` があってもなくても）。
- 知らない `key`: `404`。まだ一度も公開していないときも `404`。

`key` は次の10個。アプリの `src-tauri/src/characters.rs` の `KEYS` と同じ。

| key | 中身 | 元のファイル（このリポジトリの履歴） |
|---|---|---|
| `stage0` 〜 `stage5` | 成長段階 0〜5 | `src/assets/evo/01.png` 〜 `06.png` |
| `dandelion` | 開花: たんぽぽ | `src/assets/evo/07.png` |
| `peony` | 開花: ぼたん | `src/assets/evo/08.png` |
| `blueSpiderLily` | 開花: 青い彼岸花 | `src/assets/evo/09.png` |
| `nightCherry` | 開花: 夜桜 | `src/assets/evo/11.png` |

元のファイルはリポジトリから消した。v3.0.0 でリポジトリを作り直したので、このリポジトリの履歴にも無い。
取り出すときは、非公開のリポジトリ `kumamorun-app-archive` のクローンで `git show b973feb:src/assets/evo/01.png > 01.png` のように、消す前のコミットから出す。

### `POST /evolve` の変更

デモ版のアカウントには `403`（`{ "error": "demo_edition" }`）を返し、段階と花を変えない。アプリはデモ版では呼ばないが、サーバーでも止める。

### 変えないもの

`PUT /settings`（スタート制限の保存）は、デモ版でも受け付ける。アプリはデモ版では送らない。完全版に戻ったときに、設定が残っているようにするため。

## 画像の置き場所

**サイトのリポジトリ（kumamorun-projects）も PUBLIC なので、画像をリポジトリに入れない。**

Workers KV に置く（R2 は Cloudflare のアカウントに支払い情報が要るため、無料のままの KV にした）。
公開の URL は持たず、Worker の `GET /characters/{key}` だけが読み出す。置いた画像（下書き）と配る画像（公開した組）は分ける。
詳しい形はサイトの `docs/demo-edition.md`。

| 置き場所 | 中身 |
|---|---|
| KV `characters-draft:<key>` | 下書き。管理者が `/admin` から置き直すのはここだけ。端末には渡さない |
| KV `characters-release:<version>:<key>` | 公開した組。公開のときに下書きの10枚を写し、そのあとは変えない |
| D1 `character_releases` | 公開の記録。いちばん新しい行が公開中の版 |

- 版は時刻に乱数を足して作る（例 `2026-11-23T06.30.12.345Z-1a2b3c4d5e6f`、37文字）。アプリは形に頼らない。
- 古い版の組は、次の版が出てから1日たったら消す。アプリは同期のすぐあとに10枚を取るので、ふつうは当たらない。当たったら `404` になり、置かずに取り直す。

### `/sync` は、公開から1分たった版だけを配る

管理者が新しい組を公開しても、`/sync` の `charactersVersion` が新しい版に変わるのは**公開から1分後**。
`/sync` が返すのは、**公開から1分たった版のうち、いちばん新しい版**（1つもなければ `null`）。
「1つ前の版」ではない。たとえば A を公開して30秒後に B を公開すると、B の公開の直後も A はまだ1分たっていないので、
A も B も配らない（それより前の版か `null` のまま）。A は公開から1分、B は公開から1分たった時点で、それぞれ配り始める。
（サイトの `src/server/edition.ts` の `readCharactersVersion`）

- 理由: KV は書いた値が世界中で読めるまでに最大60秒ほどかかる。行き渡る前に新しい版を配ると、遠くの端末が画像を取りに行って `404` になりうるため、配り始めるのを遅らせている。
- アプリの動きは変わらない。`charactersVersion` が変わったら、その版を `?v=` に付けて10枚を取る。同期は最大10分ごとなので、利用者から見ると、公開してから最大11分ほどで画像が変わる。
- 10枚を取り終えたら、版が変わるまで取り直さない。取れなかったときは、間隔を延ばして取り直す。
- 試験で、公開の直後に `/sync` の版が変わることを前提にしない（1分待つ）。

## 承認の画面（サイト）

- 管理者だけが開けるページで、アカウントの一覧（名前、メール、登録日、承認の有無）を見せる。
- 「承認する」で `approvals` に行を足し、「取り消す」で消す。
- 管理者は、環境変数などで決めた account_id かメールアドレスで判定する。
- 利用者向けのページ（状況ページなど）には、自分がデモ版か完全版かと、デモ版なら「承認を待っています」を出す。承認の申し込み方法（フォーム、連絡先）はサイト側で決める。

承認すると、アプリは次の同期（最大10分後。アカウント画面を開けばすぐ）で完全版になり、画像を受け取る。
取り消すと、次の同期でデモ版に戻り、受け取った画像を端末から消す。

## アプリの動き（実装済み）

- 版は `GET /sync` の `edition` で決める。端末の保存（`state.json` の `edition`）に控え、つながらない間も控えの版で動く。版のない古い保存ファイルはデモ版として読み、次の同期で正しい版になる。
- 完全版で `charactersVersion` が変わったら、その版を `?v=` に付けて10枚すべてを取り、そろってから `アプリのデータフォルダー/characters/` に置く。1枚でも取れなければ置かない（シルエットのまま）。
- WebView には `character://` のプロトコルで渡す。完全版の間だけ返し、キャッシュさせない。
- ログアウト、トークンの失効、`edition` がデモ版になったときは、デモ版に戻して画像を消す。
  `GET /characters/{key}` か `POST /evolve` が `403` を返したときも、ログインは残したまま、すぐにデモ版に戻す。
- 画像の差し替えは、作業用のフォルダー（`characters.tmp`）にそろえてから入れ替える。失敗しても前の版が残る。
- 実装: `src-tauri/src/edition.rs`、`src-tauri/src/characters.rs`、`src-tauri/src/cloud/worker.rs`。

## 公開の手順

**サイトを先に出す。** アプリは `edition` が欠けているとデモ版として扱うので、アプリを先に出すと、既存の利用者が一時的にデモ版になる。

1. サイト: `approvals` のマイグレーション、既存アカウントの移行、API の変更を本番に出す。`/admin` で10枚の画像を置き、1分ほど待ってから「公開」する。
2. 確かめる: 公開から1分たってから、既存のアカウントで `GET /sync` が `"edition": "full"` と版を返し、`GET /characters/stage0?v=<版>` が PNG を返す。新しいアカウントでは `"demo"` と `403`。
3. アプリ: 新しい版を出す（[docs/release.md](../release.md)）。
4. 既存の利用者が更新すると、最初の同期まではシルエットで、同期の後に画像が出る。

## 守れないもの

- 2.6.5 までに配ったインストーラーには、完全版の画像が入っている。消せないので、これまでに配った分は守れない。守れるのは、これから先に広がる分。
- v2.6.5 までの git の履歴・タグ・PR と、旧 Electron 版（`electron` ブランチ）にも画像が入っている。v3.0.0 で、これらは非公開の `kumamorun-app-archive` に移し、公開のリポジトリからは外した（[repo-split.md](repo-split.md)）。誰かが前に取ったクローンは消せない。
- アプリのアイコン（`src-tauri/icons/`）はキャラクターの小さな絵。インストーラーとタスクバーに出るので、外せない。
- 承認された端末には画像が置かれる。承認した人が取り出すことは防げない。
